# 장애 RCA 리포트

대상은 `incident-logs/$ARGUMENTS/` , 결과는 `docs/rca/$ARGUMENTS.md` 다.

## 절차

1. **수집 범위** — 로그를 통째로 읽지 않는다. 먼저 `wc` · `head` · `tail` · `grep -c` · `awk` 분 단위 집계로 파일별 줄 수 · 기록 기간 · 시각 형식 · 타임존을 표로 정리한다.
   - 타임존이 다른 파일은 KST 변환 규칙을 적고, 다른 파일과 건수 · 시각이 일치하는지로 확인한다.
   - 평소 수준과 이상 구간을 정하고, 앞뒤 여유를 둔 수집 범위를 정한다.
2. **타임라인** — 수집 범위 안의 사건을 시각순으로 적는다. 모든 줄에 `파일:줄번호` 와 원문 발췌를 붙인다.
   - 초 단위 로그 사이에서 선후를 알 수 없으면 "(선후 불확실)"로 표시한다. 이 단계에서는 원인을 해석하지 않는다.
3. **가설** — 계층이 다른 가설을 2개 이상 세운다(코드 · DB · 트래픽 · 배포 설정 등). 가설마다 지지 근거, **반증 조건**, 확인 방법(명령)을 적는다. 증상(풀 고갈, 5xx)과 원인을 구분한다.
4. **검증** — 먼저 로그로 반증을 시도하고 실행한 명령과 결과를 기록한다. 그다음 코드 · 설정과 대조한다. 가설마다 채택 · 기각 · 판단 불가를 판정하고 이유와 확신 수준을 적는다. 실행하지 못한 확인은 숨기지 않는다.
5. **리포트 작성** — `docs/rca/$ARGUMENTS.md` 에 다음 순서로 쓴다.
   요약 → 원인(직접 · 배경, 인과 순서) → 근거 로그 줄(`파일:줄번호` + 발췌) → 수정안 → 재발 방지 → 모니터링 항목(임계값 · 이번에 울렸을 시각) → 확인하지 못한 것(이유 · 앞으로 남길 로그)
6. **마스킹** — 리포트를 저장하기 전에 `.claude/skills/rca/masking-rules.md` 의 규칙을 적용한다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 인용 전에 줄번호를 다시 열어 확인한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 그 오류가 왜 생겼는지까지 내려간다.
- 원본 로그와 소스 코드를 수정하지 않는다. 수정안은 제안으로만 적는다.
- 마스킹 대응표를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
