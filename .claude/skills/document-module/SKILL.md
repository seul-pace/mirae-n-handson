# 레거시 모듈 문서화

분석 대상 폴더(`$ARGUMENTS` 의 모듈 경로)의 파일은 읽기만 한다. 수정 · 생성 · 삭제하지 않는다.
쓰는 곳은 `docs/<모듈명>/` 뿐이다.

## 0. 모듈명 정하기
`<모듈명>` 은 폴더 이름이 아니라 아래 셋 중 하나다. 목록에 없는 경로면 멈추고 묻는다.
- `legacy/item-bank-php` → `item-bank`
- `legacy/assignment-thymeleaf` → `assignment`
- `legacy/grade-mssql` → `grade`

## 1. 계획 먼저 제시
파일 목록(Glob)만 보고 분석 범위 · 읽을 파일 · 단계별 산출물을 짧게 제시한다. 두 번째 인자(범위 제한)가 있으면 그 범위로 좁힌다. 계획을 보여 준 뒤 분석을 시작한다.

## 2. 단계 — 단계가 끝날 때마다 파일로 저장한 뒤 다음 단계로 넘어간다
1. **진입점**: 라우트 · 컨트롤러 · 페이지 · 스케줄러 · 배치를 표로(경로, 메서드, 처리 파일:줄). → `ARCHITECTURE.md` 에 저장
2. **의존 관계**: 계층 · 모듈 간 호출 방향(누가 누구를 부르는지)과 외부 의존(DB, 설정, 라이브러리). 호출은 실제 호출 줄로 확인한다. → `ARCHITECTURE.md` 에 덧붙여 저장
3. **데이터 흐름**: 요청 → 검증 → 저장 → 응답 경로와 읽고 쓰는 테이블 · 컬럼, JOIN · FK. 스키마 기준은 `db/` 의 DDL. → `ERD.md` 에 저장(Mermaid `erDiagram` + 테이블별 사용처)
4. **비즈니스 규칙 후보**: 조건 분기 · 상수 · 상태 코드 · SQL WHERE · 검증 메시지에서 규칙을 뽑는다. → `BUSINESS-RULES.md` 에 저장

문서 머리에 분석 범위 · 경로 약어 · "코드가 하는 일을 적은 후보이며 의도된 정책인지는 확인하지 않았다"를 적는다.

## 3. 규칙 형식
```
**BR-01**
- 규칙: (코드가 실제로 하는 일을 한 문장으로)
- 근거: `파일:줄번호`(범위는 `:63-66`), 호출 위치가 따로 있으면 함께
- 근거 코드:
  (해당 줄을 그대로 인용한 코드 블록)
- 확신도: 확실 | 높음 | 추정
- 비고: 주석 · 다른 구현과의 불일치, 도달 가능 여부, 적용 범위
```
주석과 코드가 다르면 코드를 규칙으로 삼고 차이는 비고와 불일치 표에 적는다.

## 4. 하지 말 것 (실제로 틀렸던 유형)
- 앞 단계에서 걸러져 도달하지 않는 분기를 도달 가능한 규칙으로 적지 않는다. 조회 SQL 의 INNER JOIN · FK 로 이미 빠지는 경우("학급이 없어도 진행", "과제 없으면 E102")를 확인한다.
- 같은 검사가 여러 곳(컨트롤러와 서비스 등)에 있으면 한 곳만 적지 않는다. 전부 근거로 단다.
- 조건의 적용 범위를 생략하지 않는다. `allowed && x == 1` 처럼 앞 분기와 이어지는 조건은 어느 경로에서 적용되는지 적는다.
- 코드의 사용자 메시지 문구("마감 당일")를 그대로 규칙으로 옮기지 않는다. 실제 비교식(24시간 이내 등)으로 적고 문구는 비고로.
- 근거 줄 범위를 중간에서 자르지 않는다. `if` 부터 `throw` 블록 끝까지 포함한다.
- 가공 순서가 결과를 바꾸는 규칙(자른 뒤의 값으로 분류 등)을 빠뜨리지 않는다.
- 주석-코드 불일치는 실제로 결과가 어긋날 때만 불일치로 분류한다.
- 존재하지 않는 함수 · 파일 · 줄을 근거로 쓰지 않는다. 인용한 코드는 Read 로 연 그 줄과 글자 그대로 같아야 한다.
- 호출 방향을 이름으로 짐작하지 않는다. 호출 줄을 찾지 못했으면 "확인 필요"로 남긴다.
- 코드에 없는 규칙(일반적인 업무 상식, 요청에 있었지만 코드가 없는 기능)을 만들지 않는다. 해당 코드가 없으면 "이 모듈에 없음"이라고 적는다.

## 5. 마무리 — 사람이 표본 점검할 규칙 3개 추천
답변 끝에 규칙 3개를 추천한다. 각각 ID, 한 줄 요약, 고른 이유, 확인할 파일:줄을 적는다.
- 1개는 가장 그럴듯한 규칙(확신도 "확실"이고 상식과 맞아 검토 없이 넘어가기 쉬운 것)
- 1개는 확신도가 가장 낮거나 도달 여부 · 적용 범위가 애매한 것
- 1개는 불일치(두 곳에 다르게 구현, 주석과 코드 차이)를 담은 것
