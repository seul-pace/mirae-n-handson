# 머지 전 검증

검증 대상: $ARGUMENTS

- 검증 대상이 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.
- 코드를 직접 고치지 않는다. 판정과 이슈 목록만 보고한다.
- 절차의 배경(만든 쪽과 검증하는 쪽의 분리, 역할)은 저장소 루트의 `templates/verification-loop.md` 에 있다.

## 1. 요청 범위 확인
- 무엇을 요청한 변경인지 한 문장으로 확인한다.
- 요청 문장이 주어지지 않았으면 판정하지 말고 먼저 묻는다. 추측한 범위로 진행하지 않는다.

## 2. 변경 파일 목록과 diff 읽기
- 범위가 git 범위면 `git diff --stat <범위>` 로 목록을 먼저 보고, 파일마다 `git diff <범위> -- <파일>` 로 읽는다.
- patch 파일이면 `git apply --stat <파일>` 로 목록을 뽑고 patch 본문을 읽는다. patch 를 작업 트리에 적용하지 않는다.
- 이슈에 적을 줄번호는 diff 의 추정값이 아니라 현재 파일을 Read 해서 확인한 값만 쓴다. patch 파일이면 patch 안의 줄번호를 쓴다.

## 3. 체크리스트 대조
- 저장소 루트의 `templates/approval-checklist.md` 를 읽는다. 항목과 심각도 정의는 그 파일이 기준이다.
- 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시한다.
- 컨벤션 기준은 저장소 루트의 `CLAUDE.md` 와 `convention-check` Skill 의 결과를 쓴다.

## 4. 테스트 실행
변경된 폴더의 테스트만 실행한다.

| 바뀐 곳 | 명령 |
|---|---|
| `modern/api` | `cd modern/api && ./gradlew test` |
| `modern/web` | `cd modern/web && npm test` |
| 이관 코드 | `cd characterization && npm test` (레거시 대상) 와 `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

- 출력은 통과 · 실패 수와 실패한 테스트 이름만 남긴다. 전체 로그를 대화에 싣지 않는다.
- 실행할 수 없었으면(서버 꺼짐, 의존성 미설치) 그 사실과 명령을 적고 사람에게 기동을 요청한다. "테스트 통과"는 미충족으로 둔다.
- `characterization/` 의 테스트 코드 · 스냅샷은 실패해도 고치지 않는다. 실패한 케이스와 차이를 그대로 보고한다.

## 5. 승인 기준 판정
- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다.
- 네 기준이 모두 충족이면 승인, 하나라도 미충족이면 반려다.
- 이슈가 0건이면 경고 · 제안 수준까지 diff 를 한 번 더 본 뒤 결과를 낸다.

## 6. 출력 형식 (이 순서로 고정)

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수, 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|

확인 필요
- 근거 줄번호를 특정하지 못한 의심 사항. 없으면 이 절을 생략한다.
```

- 이슈 한 건은 심각도(치명 / 경고 / 제안) · `파일:줄번호` · 근거 · 수정 방향 순서로 적고 네 항목을 모두 채운다.
- 경로는 저장소 루트 기준으로 쓴다.
- 이슈가 없으면 표 대신 "이슈 없음" 한 줄을 쓴다.

## 7. 하지 말 것
- 코드를 수정하지 않는다.
- 근거 줄번호를 댈 수 없는 지적은 하지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 요청 범위를 모르는 상태에서 "요청 범위 이탈 없음"을 충족으로 표시하지 않는다.
